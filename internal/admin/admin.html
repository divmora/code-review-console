Repositories appear here automatically when they send their first webhook, set to Inherit: they follow the most specific group or pattern rule, and otherwise the default (). Choosing Enabled or Disabled here overrides every rule. Settings here override the rules' settings and the repository's own .codereview.yaml.

Each host is a GitHub (github.com or Enterprise), GitLab (gitlab.com or self-managed) or Bitbucket Cloud account the console reviews for. Tokens and webhook secrets are encrypted with CODEREVIEW_CONSOLE_SECRET_KEY before they are stored and are never shown again: leave a secret blank to keep it. Point each code host's webhook at the URL shown, with the events listed. Several hooks on one host (a GitLab system hook plus group hooks) can each have their own secret: add one per line.

Levels, broadest first: Settings (everything) → whole host (empty pattern) → group or owner (acme, acme/platform, subgroups included) or pattern (acme/svc-*; * stays within one level) → repository. For each setting the most specific level that sets it wins; Inherit means "use the level above". Review settings add up the same way. Hosts are separate: a rule for acme on one host never touches acme on another.
